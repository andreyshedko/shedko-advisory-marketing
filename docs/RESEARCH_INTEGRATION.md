# Облачный поиск ChatGPT → приложение Shedko

## Поток данных

Облачная задача ChatGPT исследует публичные источники и сохраняет JSON-пакеты в репозитории приложения `andreyshedko/shedko-advisory-marketing`, ветка `codex/marketing-automation`, каталог `research/batches/`. Приложение забирает пакеты, сохраняет компании и доказательства в PostgreSQL, ставит задачи на проверку и показывает историю импорта.

Поиск может выполняться, пока компьютер выключен. Локальная панель обновляет базу при следующей синхронизации. Она не является постоянно доступным облачным сервером. Автопроверка работает, пока открыта страница компаний; после публикации на Vercel дополнительная синхронизация вызывается ежедневным Cron.

Репозиторий приложения публичный. Пакеты исследования содержат только публичные сведения компаний и источники. Секреты, внутренняя переписка, пароли и маркетинговые результаты туда не записываются.

## Формат JSON v1

```json
{
  "version": 1,
  "runId": "chatgpt:2026-10-24",
  "producer": "chatgpt",
  "query": "International M&A advisers, software acquirers and due diligence partners",
  "researchedAt": "2026-10-24T07:00:00Z",
  "records": [
    {
      "name": "EXAMPLE ONLY — not a real prospect",
      "website": "https://example.org",
      "country": "Not confirmed",
      "kind": "acquirer",
      "relevance": "Example of a documented acquisition focus and a clearly labelled partnership hypothesis.",
      "contactChannel": "https://example.org/contact",
      "sources": [
        {
          "url": "https://example.org/about",
          "note": "EXAMPLE ONLY: state the factual evidence from a page actually opened during research."
        }
      ]
    }
  ]
}
```

Это демонстрация формата; не загружайте её как реальный результат. Дата должна быть фактической, не будущей. Допустимые `producer`: `chatgpt`, `codex`, `manual`; это объявленный источник данных, не криптографическое подтверждение происхождения. Допустимые `kind`: `advisor`, `acquirer`, `search_fund`, `private_equity`, `corporate_ma`, `directory`, `partner`.

До 50 компаний, 1–5 источников на компанию, до 1 МБ. `contactChannel` необязателен; неизвестные имена, страны и контакты не угадывать. `country` может быть `Not confirmed`. Запрещены поля автоматического утверждения/верификации. Контакты для рассылки отдельно добавляются и проверяются оператором.

`runId` уникален для одной неизменной порции данных. Повтор идентичного пакета пропускается без новых записей. Изменённое содержимое с прежним `runId` отвергается; исправление оформляется новым пакетом и новым ID.

## Правила сохранения

- Новые компании и источники сохраняются **непроверенными**, с задачей для оператора.
- Совпадение нормализованного домена привязывает доказательства к существующей компании; её статус, описание, контакты и дата ручной проверки не перезаписываются.
- Совпадение имени с другим доменом или неоднозначное совпадение сохраняется как конфликт для ручной проверки. Слияние автоматически не выполняется.
- Отказы от обращений и подтверждённые источники сохраняются. Импорт не создаёт контакты для отправки, письма, заявки или платежи.

## Облачная задача ChatGPT

Задача должна иметь доступ к GitHub-подключению с правом записи **только в inbox приложения**. Если оно возвращает 404/403, пользователь добавляет репозиторий к доступу подключённого GitHub. Не обходить ограничения и не писать вместо этого в публичный репозиторий.

Рекомендуемое расписание — ежедневно в 09:00 Europe/Prague, до пяти новых содержательно релевантных компаний за запуск. Создание облачного чата и создание расписания — разные действия: расписание считается включённым только после подтверждения ChatGPT Scheduled. Инструмент локальных Codex automations не заменяет облачный планировщик.

Сначала проверяется наличие `research/batches/YYYY-MM-DD.json` за текущую дату в Праге. Если пакет уже есть, повторно его не переписывать. Использовать официальные сайты компаний, открывать страницы и сохранять ссылки. Не утверждать заинтересованность в партнёрстве без доказательства: коммерческая релевантность — гипотеза. География: США, Великобритания, Европа, Канада; типы компаний чередовать. Письма, формы и платные действия не выполнять.

## Серверная синхронизация GitHub

```
RESEARCH_GITHUB_REPOSITORY=andreyshedko/shedko-advisory-marketing
RESEARCH_GITHUB_BRANCH=codex/marketing-automation
RESEARCH_GITHUB_TOKEN=
RESEARCH_GITHUB_PUBLIC=true
```

Для публичного репозитория включите `RESEARCH_GITHUB_PUBLIC=true`: чтение работает без токена в рамках квоты публичного GitHub API. Для приватного репозитория или отдельной квоты можно использовать fine-grained GitHub token: доступ только к этому репозиторию, Contents: read. Хранить как серверный секрет, не в браузере или промпте. Облачная задача должна иметь право записывать файлы, приложение только читает. Адрес репозитория и право читать его содержимое сами по себе не доказывают право записи у подключения ChatGPT.

Локальный вариант `RESEARCH_GITHUB_LOCAL_CLI=true` использует уже авторизованный `gh` без копирования его токена. Этот вариант принудительно выключен в Vercel. Выбор inbox не меняет видимость других репозиториев.

Ручной запуск:

```sh
npm run research:sync
```

Пока страница компаний открыта, она делает запрос синхронизации раз в минуту; сервер ограничивает автоматические проверки до одной в пять минут. Кнопка «Синхронизировать» запускает явную проверку. За раз обрабатывается до трёх пакетов, оставшиеся ждут следующего запуска. SHA обработанных файлов сохраняются. Неверный пакет или отказ доступа отражается как ошибка интеграции, не как успешный обмен. GitHub Contents API возвращает до 1000 файлов в каталоге; старые уже импортированные пакеты необходимо архивировать, прежде чем достичь этого лимита.

## Дополнительный HTTPS-приёмник

`POST /api/research/ingest`, JSON v1, `Authorization: Bearer <RESEARCH_INGEST_SECRET>`. Секрет минимум 24 символа. Он разрешает только импорт исследований, не чтение всей базы, отправку писем или изменение рекламы. Отсутствующий или неверный ключ — 401. Это API для подходящего интеграционного клиента, а не автоматически подключённый инструмент ChatGPT.

ChatGPT не получает доступ к произвольному HTTP-инструменту только от наличия URL. Для прямого вызова из ChatGPT нужен поддерживаемый подключённый инструмент/MCP с соответствующей авторизацией. В реализованном облачном пути используется подключение GitHub, а не раскрытие секретного ключа в чате.

## JSON и локальная загрузка

На странице компаний есть «Импорт JSON». Он требует сессию администратора и тот же контракт. Через CLI:

```sh
npm run research:import -- /absolute/path/to/research.json
```

По умолчанию CLI сохраняет в локальную БД. Если задан `RESEARCH_INGEST_URL`, он передаёт пакет по HTTPS (HTTP разрешён только для localhost) с серверным секретом из окружения. Перенаправления отключены; исходный файл остаётся для безопасного повтора.

## Проверяемая готовность

Готовность импорта, доступа к inbox приложения, облачного чата и регулярного расписания проверяется отдельно. Настроенное имя репозитория не означает, что ChatGPT уже может туда писать. Настроенный облачный поиск не означает, что Vercel уже имеет read-only доступ к inbox.

Источники: [ChatGPT Scheduled](https://learn.chatgpt.com/docs/automations), [GitHub repository contents API](https://docs.github.com/en/rest/repos/contents).
